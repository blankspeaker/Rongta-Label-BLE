# Building Rongta-Label-BLE

Developer notes. End users should install the package from the latest release. See the README.

by [blankspeaker](https://x.com/blankspeaker) and [Grok Bot](https://x.ai/bot)

PPDs are generated by `ppd/gen_ppds.py`. The print path is the raster filters plus a Swift Bluetooth LE sender. A Python interpreter is not required to print.

## Models

| Model | Language | Filter | PPD |
| --- | --- | --- | --- |
| RP420 | ZPL | `rastertozpl-rt` | `Rongta_RP420_ZPL_203dpi.ppd` |
| RP421A | ZPL | `rastertozpl-rt` | `Rongta_RP421A_ZPL_203dpi.ppd` |
| RP425 | ZPL | `rastertozpl-rt` | `Rongta_RP425_ZPL_203dpi.ppd` |
| Rongta ZPL 203dpi | ZPL | `rastertozpl-rt` | `Rongta_ZPL_203dpi.ppd` |
| RP422 | TSPL | `rastertotspl-rt` | `Rongta_RP422_TSPL_203dpi.ppd` |
| Rongta TSPL 203dpi | TSPL | `rastertotspl-rt` | `Rongta_TSPL_203dpi.ppd` |

The generic models are for other Rongta printers that use the same 203 dpi ZPL or TSPL command set. This driver does not support 300 dpi heads.

## What a job looks like

CUPS rasterizes the page at 203 dpi, 8-bit black. `rastertozpl-rt` turns that into a ZPL graphic (`^GFA`). The default graphic is Z64: the packed bits are zlib-compressed at the highest level, base64-encoded, and followed by a CRC-16/CCITT (XMODEM) of that base64 text. `rtGfa=Hex` keeps the older ASCII-hex form. Jobs use CRLF, `^MMT` (tear-off), and `~SD` for darkness. `rastertotspl-rt` turns the same raster into a TSPL `BITMAP` wrapped in `SIZE`, `GAP` or `BLINE`, `CLS`, and `PRINT`.

Dither choices:

- **Threshold** (default). Keeps text and barcodes sharp.
- **Floyd-Steinberg**, **Ordered Bayer**, and **Clustered dot** for photos and gray artwork.

The filter writes printer commands to stdout. The `rongta-bt` backend forwards the job to a per-user helper. The helper writes characteristic `FF02` on service `FF00`. Each chunk is the printer's write-without-response length, capped at 512 bytes. If that length is still below 100 bytes, the helper waits 0.4 seconds and then uses the settled length (at least 20 bytes). Chunks go out write-without-response except the last, which is write-with-response. That acknowledgement finishes the job. A 5 second timer finishes it only if the acknowledgement never arrives. The helper keeps the connection for 20 seconds so the next label can skip discovery, then disconnects. A device URI looks like `rongta-bt://<name-prefix-or-uuid-or-auto>`. The helper looks for BLE service `FF00` and writable characteristic `FF02`. If the device does not have that characteristic, the job fails with a message that names those two ids. `SCAN` lists advertisers whose name starts with `RP4`, plus any advertiser of service `FF00`. `SCAN ALL` also lists every other advertising peripheral: named ones by their name, unnamed ones as `Unknown device` plus a short id. A device that is not a Rongta-style name is addressed by its peripheral UUID, which is stable across scans. The CUPS backend's own discovery stays on `SCAN`, so `lpinfo` does not offer unrelated Bluetooth devices.

## What the installer copies

- `/usr/libexec/cups/filter/rastertozpl-rt`
- `/usr/libexec/cups/filter/rastertotspl-rt`
- `/usr/libexec/cups/backend/rongta-bt`
- `/Library/Printers/PPDs/Contents/Resources/Rongta_*_203dpi.ppd`
- `/Library/Application Support/com.blankspeaker.rongta-label/` (`rongta-ble`, uninstaller, the README)
- `/Library/LaunchAgents/com.blankspeaker.rongta-label.plist`
- `/Applications/Rongta Label Setup.app`

The installer does not create a queue. Rongta Label Setup does that. macOS asks for a password when a queue is created, enabled, or removed.

The setup app does not start Bluetooth itself. It sends `SCAN` to the launchd helper on `127.0.0.1:47221`. That helper is `rongta-ble`, ad-hoc signed as `com.blankspeaker.rongta-label.ble`. If the helper is not running, the app runs `launchctl kickstart gui/$UID/com.blankspeaker.rongta-label`. Socket `STATUS` reports authorization and radio state without starting a scan. `rongta-ble --status` creates a manager and can prompt if Bluetooth has not been decided. Add printer runs `lpadmin` with `PageSize=4x6in`, then `lpadmin -d`, `cupsenable`, and `cupsaccept`. `lpadmin -d` runs as root and does not set the logged-in account, so the app then runs `lpoptions -d` as that user. A Mac with no printers makes `lpstat` exit with "No destinations added"; the app treats that as an empty list. The CUPS backend runs `rongta-ble --send`. It does not use netcat.

Picture choices on screen are Sharp, Photo, Fine pattern, and Soft pattern (stored as Threshold, FloydSteinberg, Bayer, and Clustered). Save writes queue defaults with `lpadmin -p <queue> -o key=value`, then reads them back with `lpoptions -p <queue> -l`.

Calibrate stores `rtInsetLeft`, `rtInsetRight`, `rtInsetTop`, and `rtInsetBottom` at 8 dots per millimetre (203 dpi). `rtLabelHomeX` and `rtLabelTop` stay at +20 and −20 unless a job sets them. `rongta-testprint` sends the matching edge-test page from the command line. A custom size uses the installed `edge-test.py` when `python3` is available.

## Add a printer

Leave the printer powered on and unpaired. Pairing it in Bluetooth settings makes CoreBluetooth less reliable; the helper connects by itself.

The helper has to run inside a graphical login so macOS can grant Bluetooth permission:

```sh
launchctl print "gui/$(id -u)/com.blankspeaker.rongta-label"
```

If that is not loaded, log in on the console, or bootstrap the agent:

```sh
launchctl bootstrap "gui/$(id -u)" /Library/LaunchAgents/com.blankspeaker.rongta-label.plist
```

Discover devices (the list includes `rongta-bt://auto` even when the helper is still starting):

```sh
lpinfo -v | grep rongta
```

A longer scan, with names and CoreBluetooth UUIDs:

```sh
"/Library/Application Support/com.blankspeaker.rongta-label/rongta-ble" --scan
```

Add a queue. `auto` selects a peripheral whose name starts with `RP4`, or any peripheral advertising service `FF00`. A name prefix such as `RP425` matches that family. A UUID pins one peripheral. The sample below is not a real device:

```sh
lpadmin -p Labels -E \
  -v "rongta-bt://auto" \
  -P "/Library/Printers/PPDs/Contents/Resources/Rongta_RP425_ZPL_203dpi.ppd" \
  -D "Rongta RP425" \
  -o PageSize=4x6in
```

The first send prompts for Bluetooth access for `rongta-ble`. Allow it. If the prompt was dismissed, enable `rongta-ble` under Privacy & Security → Bluetooth, then kick the helper:

```sh
launchctl kickstart -k "gui/$(id -u)/com.blankspeaker.rongta-label"
```

Logs from the helper are appended to `~/Library/Logs/com.blankspeaker.rongta-label.log`.

Print a file:

```sh
lp -d Labels -o PageSize=4x6in label.pdf
```

## Calibration options

Offsets are printer options, so they travel with the job. Defaults are **+20 dots horizontal** and **−20 dots vertical** (`^LH20,0` and `^LT-20`). Those stay as they are.

A full-bleed 4×6 page on an RP425 was clipped about 1 mm on the left, 1 mm on the right, and 4 mm at the top; the bottom was flush. That offset is the print head, not the 4×6 layout: the top 4 mm is the sensor-to-head gap and applies to every label height. The filters scale the 8-bit raster into that inset with an area average before dithering, and leave the margins white. At 203 dpi, 8 dots is 1 mm, so the ZPL default is **8, 8, 32, 0** dots on every page size. A 2×1 label is 406×203 dots, so those insets still leave a printable box. The filter rejects a page the inset does not fit, such as a height of 32 dots with the 32-dot top inset. Limiting the default to 4×6 would full-bleed-clip every other size. TSPL defaults stay 0 until that path is calibrated the same way. Set every inset to 0 to pass the raster through unchanged.

| Option | Default | ZPL | TSPL |
| --- | --- | --- | --- |
| `rtLabelHomeX` | `20` | `^LHx,0` when x ≥ 0, otherwise `^LS` of the absolute value (positive `^LS` moves the image left) | `REFERENCE x,0` |
| `rtLabelTop` | `-20` | `^LT` (legal range −120…120). Negative moves the image up | `OFFSET y dot` |
| `Darkness` | `7` | `~SD` with the option value (0…15). `~SD` itself accepts 0…30; 7 sends `~SD7` | `DENSITY` 0…15, absolute |
| `PrintSpeed` | `5` | `^PR` inches per second, 2…6 | `SPEED` |
| `MediaType` | `Gap` | `^MNW`, `^MNN`, or `^MNM` | `GAP`, `GAP 0`, or `BLINE` |
| `rtGapMm` | `2` | not used | gap or black-mark height in millimetres |
| `rtDither` | `Threshold` | both filters | both filters |
| `rtInvert` | `False` | flip black and white if a printer treats the graphic polarity backwards | same |
| `rtGfa` | `Z64` | `Z64` compressed `^GFA`, or `Hex` for ASCII hex | not used |
| `rtInsetLeft` | ZPL `8`, TSPL `0` | dots left blank; the page is scaled into the rest | same |
| `rtInsetRight` | ZPL `8`, TSPL `0` | dots right blank | same |
| `rtInsetTop` | ZPL `32`, TSPL `0` | dots at the top of the raster left blank | same |
| `rtInsetBottom` | `0` | dots at the bottom left blank | same |

Example: nudge a 4×6 label 10 dots further right and turn the threshold back to a plain black cut.

```sh
lp -d Labels -o PageSize=4x6in -o rtLabelHomeX=30 -o rtLabelTop=-20 -o rtDither=Threshold label.pdf
```

`lp -o` accepts any in-range integer, including values that are not in the print dialog list. `rtLabelHomeX` is −800…800. `rtLabelTop` is −120…120. Each `rtInset*` value is 0…800 dots.

`examples/edge-tests/` has one PDF per PPD page size, and `examples/edge-test.pdf` is the 4×6 page. The outline is drawn on the true page edge. The driver inset is what pulls that line in, so with the ZPL defaults the outline sits 8 dots from the left and right and 32 dots down from the top on every size. The installer copies them to `/Library/Application Support/com.blankspeaker.rongta-label/edge-tests/` and keeps `edge-test.pdf` as the 4×6 fallback.

```sh
"/Library/Application Support/com.blankspeaker.rongta-label/rongta-testprint"
"/Library/Application Support/com.blankspeaker.rongta-label/rongta-testprint" Labels
```

Regenerate every page with `python3 examples/edge-test.py`. One size, including a custom size, is `python3 examples/edge-test.py --page-size 2x1in -o /tmp/2x1in.pdf` or `--page-size Custom.3.5x2in`. A default ZPL job for a rasterized page is:

```sh
rastertozpl-rt 1 user title 1 '' edge.raster > edge.zpl
```

An empty option list uses the ZPL inset default. `rtInsetLeft=0 rtInsetRight=0 rtInsetTop=0 rtInsetBottom=0` leaves the raster unchanged.

## Uninstall from the command line

The app's Help button runs the same script:

```sh
sudo "/Library/Application Support/com.blankspeaker.rongta-label/uninstall.sh"
```

That removes the filters, backend, PPDs, launch agent, Rongta Label Setup, and any queue whose PPD points at these filters. Per-user logs under `~/Library/Logs/` are left in place.

## Build

On Linux, the filters and the encoding tests build against libcups. The `.pkg` does not.

```sh
sudo apt install build-essential libcups2-dev zlib1g-dev
make test
```

On macOS 13 or later, with the command line tools installed. `./build.sh` targets the raster filters at macOS 11 and the Bluetooth helper at macOS 13, which is the oldest target that links a universal Swift binary with these tools:

```sh
make test
./build.sh
```

`./build.sh` writes an unsigned installer to `dist/Rongta-Label-BLE.pkg`. It tries arm64 and x86_64, and falls back to the host architecture if one of those targets cannot be built. Swift and clang are passed `-file-prefix-map`, `-debug-prefix-map`, and `-coverage-prefix-map` so the binaries do not embed the build machine's home directory or checkout path. GitHub Actions (`.github/workflows/build.yml`) runs the tests on Ubuntu and builds the package on macOS.

PPDs are generated by `ppd/gen_ppds.py`. `make ppd` rewrites `ppd/`, and the tests check that the committed files still match the generator.

Encoding tests do not need a printer. They lock the bytes of a known 8×2 raster in ASCII-hex mode (`rtGfa=Hex`): threshold packing, the default `^LH20,0` / `^LT-20`, `~SD7`, `^MMT`, and the shifted option set. The default Z64 `^GFA` path is round-tripped in the encoder test (inflate the payload and check the CRC).

These behaviors still depend on a particular printer and were not re-checked as part of every build:

- TSPL bit polarity (`rtInvert`), and the sign of `OFFSET` / `REFERENCE`
- gap, black-mark, and continuous sensor behavior, and whether darkness and speed match the panel
